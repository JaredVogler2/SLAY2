# PROMPT 03 — RUN THOUSANDS OF REAL, COMPLETE STS2 GAME SIMULATIONS

Implement and **execute** a reproducible, full-game solo experiment runner using the validated phase 02 simulator. Do not confuse a combat rollout, turn, truncated environment episode, playthrough in debug/oracle mode or partial Act1 simulation with a **completed three-act game**. The game outcome at A10 needs the second Act3 boss defeated. Every run must have version, character, Ascension, seed, choices, terminal and integrity evidence.

## Simulation protocol
- First commit a strict experiment specification: `game=STS2`, `channel=main|beta`, exact build, engine SHA, rules+dataset SHA, character, Ascension, `mode=solo`, progression/unlocks/tutorial-script state, Act3 objective, policy, visible-state schema, compute/search budget, legal action contract, max floor/turn/actions and terminal success/loss definition.
- Use fully independent seeds with manifest persisted before runs; split train/validation/blind-test at **episode and seed lineage** levels. Never expose seed value or game RNG to the agent. If mod bridge is used, sanitize observations.
- Baselines: random legal; random with don't-suicide safeguards; fixed heuristic for immediate damage/block and card rewards; danger-aware potions and healing; budget-aware route DP; search-based combat; and properly licensed existing human-observation search baseline if reproducing on consistent patch.
- Across all five characters only when proven supported. **Start Ironclad solo, A0**, then A1–A10 and Regent/Necrobinder/Silent/Defect individually. Co-op campaigns are a separately gated future stage.
- Include a robust CLI: `sim doctor`, `sim smoke --n 10`, `sim run --policy <name> --character Ironclad --ascension 0 --build <version> --seeds <manifest> --output <dir> --workers 4`, `sim audit <batch>`, `sim compare <reports>`. Exact CLI spelling may change but all capabilities are mandatory.
- Run a reproducible 10-game dry run; 100-game smoke; >=2,000 *actually completed* benchmark games initial fully supported configuration; target >=10,000 complete games per policy family subject to bounded user compute. **Don't fabricate goals as achievements**; if can't reach target record exact valid count and a resumable plan.
- Support safe parallelism, atomic append-only manifests, per-worker logs and seed deduplication, checkpoints/recovery, memory/time quotas, version migration invalidation, validation/invalid/timeout accounting, and no hardware oversubscription.
- Every step log observation hash/allowed fields, legal options, choice, resulting observation, rules/model/search version, timestamps and optional explanation. Store trace JSONL compressed or columnar; NEVER include internal RNG/future unrevealed state in public training features. Internal engine outcomes may store secret debug separate from trainable/public log when essential and permitted.
- Terminal: true Act3 victory, death/loss, invalid/unsupported, timeout or abort, co-op disconnected where applicable. Invalid != defeat and aborted != win; publish denominator and separate rates. A10 double boss verified, no Heart proxy.
- Record act/floor HP, gold, deck/relics, potion usage, Ancient choices, events, map, combat stats, bosses, enemy intent conditions, enchantments, afflictions, Stars/Osty/Doom/Sly/orbs, character-specific archetype and route exposure. Aggregate stratified by boss, build, Ascension, class, early alternative act, unlock profile and policy.
- Audit action legality; no invisible cards/target, illegal purchases, no unreachable map edges, no outside-of-turn actions, no future-leakage; run seed replay bit-for-bit on deterministic fixtures and quantify deviations.
- Save artifact hashes, source commits, CPU/GPU/environment/dependency versions, worker hours, actual runs count, simulator accuracy, confidence intervals for achieved win percentages; preserve raw evidence outside repo if large, commit compact reproducible summary and manifest with storage location/checksums.
- Design experiment coverage to prevent simply training on random-agent poor choices. Contrast actual player logs (observational, confounded) with valid fair-policy simulator counterfactual rollouts; candidate action data must include observed offers and legal alternatives if truly available.

## Statistically defensible evaluation
Paired head-to-head comparisons on same unseen seed lists and fair observation, identical budgets. Use Wilson intervals for win proportions; bootstrap confidence interval of paired gains, power calculation for low win-rate A10, and predeclared thresholds and stopping. Partition patches: a data record from beta v0.111.0 does not silently join stable v0.107.1 model training.

## Delivery gate
Tested executable runner, real run summaries, reproducible commands, validation scripts, seed manifests and computed outcome confidence. If full-run parity unavailable, status BLOCKED; retain a valid analytic/small combat calculator and do not imply thousands of completed games. Commit and push before phase 04.
