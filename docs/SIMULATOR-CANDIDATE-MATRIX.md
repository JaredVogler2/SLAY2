### Hazards discovered (these change how SLAY2 must call the simulator)

1. **Exceptions are converted into losses.** `STS2RunEnv.step()` catches any exception from the simulation, logs it, and calls `lose_run()`. A naive harness would count simulator bugs as *deaths* and report "100 % completed games, 0 % wins". SLAY2's harness drives `RunManager` directly and classifies `simulator_error` separately; the gym wrapper is never used for evidence.
2. **Timeouts are also recorded as losses** (`truncated=True` plus `lose_run()`). SLAY2 classifies them as `timeout`.
3. **Hidden cwd dependency.** The card factory reads `docs/CARDS_REFERENCE.md` via a *relative* path. Run from any other directory, every first combat raised `FileNotFoundError`, which hazard 1 turned into 10/10 "deaths" on my first smoke test. The harness must `chdir` into the checkout.
4. **The opening Ancient (Neow) is skipped by default** (`RunManager(start_with_neow=False)`, which the gym env uses). The real game always starts with the Ancient event. SLAY2 sets `start_with_neow=True`; with the event registry populated (item 10) the simulated Neow offers three choices (two "positive" relics and one "cursed" relic). (An earlier draft of this document said Neow offers only "Leave"; that was an artifact of item 10, not simulator behaviour.)
5. **Per-card RNG order differs from the game.** The port rolls all three rarities, then picks cards/upgrades; the game interleaves roll -> pick -> upgrade per card. Distributions are identical (M2), but **seeds do not reproduce live-game packs**.
6. **Default profile = the profile's very first run (tutorial scripting on).** `unlock_state.number_of_runs` defaults to 0, so every simulated run gets the scripted first-run content: the first three "?" rooms are always Event, Event, Monster (measured 275/211/143 of 300 runs), and the early card/potion packs are fixed (`reward_objects.py` `TUTORIAL_*`). That is a *cohort*, not typical play. SLAY2 therefore records a `profile` for every batch: **`veteran`** (default; `number_of_runs=10`, `epoch_unlock_count=20`, tutorial off; all content unlocked by default) and **`first_run`** (simulator default).
7. **Self-reported results.** 92 % "combat win rate" is Act-1 Ironclad *combat* with a trained PPO; the repo's own `KNOWN_ISSUES.md` records **0 % full-run win rate after 1M PPO steps**.
8. **Docs drift.** README says 217-dim observation, `ascension_level` 0-20 and "Acts: 4"; the code is 237-dim, A0-A10 and 3 acts.
9. **The RNG is the pre-0.107.1 family.** The game's `MegaRandom` is xoshiro256** seeded through Splitmix64 (E1 `Random/MegaRandom.cs`; official notes "PRNG replaced in v0.107.1"); the simulator's `core/rng.py` is a port of .NET `System.Random`. Streams are named like the game's (`rewards`, `shops`, ...) but produce different numbers, so **no seed reproduces a live-game run** (closes open question Q12).
10. **Events are not registered unless `sts2_env.events` is imported**, and neither `RunManager` nor `STS2RunEnv` nor the training scripts import it. Measured: `_EVENT_REGISTRY` has 0 of 68 events after `import RunManager`; every Neow/Ancient/"?" event then degrades to a lone "Leave". *The repository's own gym/PPO training path therefore ran with no events at all.* SLAY2's `external.activate()` imports the package; all SLAY2 batches ran with the full 68 events (Neow offers three real choices).
11. **`copy.deepcopy` of a run is not a faithful forward model.** Monster move closures keep pointing at the original creatures, so a cloned combat diverges at the enemy turn: **38 of 80** random combat sequences diverged from the live run. SLAY2's closure-aware clone (`slay2_sim/clone.py`) rebinds closure cells through the copy memo: **0 of 80** diverged over 1,578 compared steps at the same ~2.3 ms per clone. This is what makes fair determinized search sound.
12. **A reproducible simulator crash exists** (found by the 2,000-game batch): `is_sovereign_blade(None)` in `cards/status.py` dereferences a missing card source when a power gained from another class's card meets an enemy attack (1 in 2,000 random games). The harness reports it as `simulator_error`, never as a loss.
13. **Three special monsters ignore A8 HP scaling** (see M5).
14. **A10 "Double Boss" is not modelled.** The game gives the final act a `SecondBossMapPoint` one row above the first boss (E1 `StandardActMap` ctor `hasSecondBoss`, `RunManager.cs` L686-689, `NMapScreen` makes it travelable after the first boss). The simulator rolls a distinct `second_boss` into the room set at A10 (`run_state.py` `has_double_boss = asc >= 10`) but its map generator only knows `boss_point`, and `_transition_next_act()` declares victory after the first Act-3 boss. Measured with a 100,000-HP player (so the win path is reachable): A0 -> win after exactly one boss fight in each act `{0: 1, 1: 1, 2: 1}`; A10 -> win after the same single Act-3 boss while `boss_encounters_visited == 1` and `second_boss` was never entered. **Consequence: every A10 result from this simulator is not a Double Boss win rate.** (`has_double_boss` is read in exactly one place, the room-set generation, so simulated A10 differs from A9 only by an unused extra boss roll.) Pinned by `sim/tests/test_terminal_semantics.py` (a strict `xfail` asserts the game-correct two fights, so an upstream fix will flip the test and force a doc update); listed in every batch manifest via `slay2_sim/gaps.py`.

### Verdict

* Usable as a **research-grade, fast, unlicensed, locally-run** environment with *unverified* live-game parity.
* **Not** shippable, not vendorable, not evidence of real win rates.
* Reaching a live-game parity claim needs a legitimately owned STS2 copy plus the MIT bridge (STS2MCP) - an owner-machine task (see `docs/RESEARCH-OPEN-QUESTIONS.md`).
